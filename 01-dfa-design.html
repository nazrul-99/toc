How to design a DFA

Take Σ = {0, 1}. A DFA reads the input once, left to right, and can only remember which state it is in. Designing one is therefore a question of deciding what the machine must remember about the part of the input already read. Every problem in this set follows the same procedure.

The design procedure

  1. Write down short examples. List a few strings that are in L and a few that are not, including ε and the strings of length 1.
  2. Decide what to remember. Ask: if I had to stop reading now, what single fact about the prefix decides the future? Each distinct fact becomes one state.
  3. Name the start state. It stands for the empty prefix ε. It is final only if ε ∈ L.
  4. Fill in the transitions. For every state and every symbol ask "what fact holds after reading one more symbol?" Exactly one arrow per symbol leaves every state.
  5. Add a trap if needed. If some prefix can never lead to acceptance, send it to a non-final state that loops on every symbol.
  6. Mark the final states. They are the states whose remembered fact means "the string read so far is in L".
  7. Test. Run the strings from step 1 through the machine. In this page you can also verify every string up to length 12.
