Part 1

Why a machine model matters

From a machine to software

  1. Model the system as states and events (what must the system remember?).
  2. Choose the weakest machine that works: a finite automaton if bounded memory is enough, a stack if nesting matters, a full program otherwise.
  3. Analyse: weaker machines can be checked, minimized and tested completely; stronger ones lose these guarantees (undecidability).
  4. Implement: state tables become switch statements, lookup tables or hardware circuits.

Rule of thumb

If the problem needs…Use
to remember one of finitely many situationsDFA / FSM (Sections 1–8)
to match nested pairs of unbounded depthCFG / PDA (Sections 9–18)
arbitrary computationa Turing machine (Section 19) and the limits of decidability
to know if it can be done fastcomplexity classes P and NP
Part 2 · DFA / Mealy machine

Metro rail ticket vending machine and gate

A ticket machine only needs to remember how much money has been inserted so far, and that amount never exceeds the fare. Finitely many possibilities, so it is a finite automaton. Because it also produces outputs (ticket, change), it is a Mealy machine: each transition is labelled input / output.

Part 3 · Verification, search, NP-completeness

Sudoku through the lens of TOC

Sudoku shows the central idea of NP in one picture: checking a filled grid is quick and mechanical, while filling an empty grid may require a long search.

Play, verify and solve

Sudoku and the classes of the course

QuestionAnswer in TOC terms
Is this filled grid correct?In P: check 3n groups of n cells, about 3n² steps. The filled grid is a certificate.
Can this partial n² × n² grid be completed?NP-complete (it is in NP because the completed grid is a short certificate, and it is NP-hard by reduction from Latin-square completion).
Is the ordinary 9 × 9 Sudoku hard?Its size is fixed, so in theory it takes constant time. Complexity talks about how time grows as the grid grows.
How do solvers work?Backtracking (a depth-first search of the configuration tree), or a reduction to SAT and a SAT solver.
Sudoku as a graphOne vertex per cell, an edge between cells in the same row, column or box: completing the grid = graph colouring with n colours.
Is "a row contains each digit once" a regular language?Yes: for a fixed n there are finitely many valid rows, and every finite language is regular, so a DFA can check one row.

Reduction to SAT: the encoding

Boolean variable x(r, c, v) means "cell (r, c) holds value v". The rules become clauses; the formula is satisfiable exactly when the puzzle can be completed. The size of the formula is polynomial, so this is a polynomial-time reduction Sudoku ≤ₚ SAT.

Part 5 · DFA for "ends with" / pattern matching

Text search: Ctrl+F, grep and the KMP automaton

To find a pattern in a long text, build the DFA that recognises "the text read so far ends with the pattern" (the same construction as problem 1.6). Each state is the length of the longest pattern prefix matched; the text is read once, left to right.

Where it is used

Editors and IDEs (find, find-and-replace), the Unix tools grep and sed, intrusion-detection systems scanning network packets for attack signatures, and DNA sequence search. Regex engines compile the pattern to an NFA or DFA in the same way.

Part 6 · DFA design, regular expressions

Input validation in apps and websites

Every sign-up form validates phone numbers, emails and IDs. Each validator is a regular expression, which is a DFA in disguise.

Bangladeshi mobile number: ^01[3-9][0-9]{8}$

States count the digits read. Every symbol without a drawn transition goes to the trap state ✗, as in Section 1.

Email (simplified): ^[\w.+-]+@[\w-]+(\.[\w-]+)+$

Green: matches. The full email standard is far more complex, but still regular.

Part 7 · CFG, parse trees, ambiguity

Compilers II: parsing expressions

After lexing, the parser checks the token sequence against a context-free grammar and builds a parse tree. The tree decides the meaning: an ambiguous grammar can give the same expression two different values.

Unambiguous grammar E → E + T | T, T → T * F | F, F → ( E ) | num

Ambiguous grammar E → E + E | E * E | num: one possible tree

Where it is used

Every compiler and interpreter (C, Java, Python), calculators, spreadsheet formulas, SQL engines, JSON and configuration-file readers. Parser generators (yacc, bison, ANTLR) take a CFG and produce a parser automatically; CYK and Earley (Section 16) parse any CFG.

Part 8 · Pushdown automata

Matching brackets and HTML tags with a stack

Nesting of unbounded depth cannot be checked by any finite automaton, but a stack handles it easily: push every opening symbol, pop on the matching closing symbol. This is a PDA (Section 17).

Stack

Where it is used

Code editors highlighting matching brackets, HTML and XML validators, JSON parsers, the browser's "back" history, the call stack of every running program, and undo/redo.

Part 9 · CFG, parse trees, PDA

Natural language and biology

Parsing English sentences

Grammar: S → NP VP, NP → Det N | Det Adj N | Name | NP PP, VP → V NP | V | VP PP, PP → P NP.

Vocabulary: the, a · student, machine, book, ticket, station, train · smart, small, new · Nazrul, Dhaka · reads, buys, builds, takes, sleeps · at, with, in, from

Used in grammar checkers, machine translation and early NLP; "the student reads a book in Dhaka" is ambiguous (who is in Dhaka?), the same phenomenon as Section 12.

RNA secondary structure

An RNA strand folds so that bases pair up in a nested way, exactly like brackets: the structure is written in dot-bracket notation and generated by a CFG such as S → aSu | uSa | gSc | cSg | SS | ε. Checking nesting needs a stack.

Part 11 · Turing machines, decidability

Computability: what software can never do

Every computer is a Turing machine

Your laptop, a phone and the Python interpreter can all simulate each other, and all can be simulated by a Turing machine (Church–Turing thesis). An interpreter or virtual machine (JVM, Python, a browser running JavaScript) is a universal Turing machine: a program that runs other programs given as input.

The halting problem in one diagram

Suppose a perfect checker H(P, x) existed that always says correctly whether program P halts on input x. Build D(P): if H says P halts on P, loop forever; otherwise halt. Now ask what D does on D: if it halts, H said it loops; if it loops, H said it halts. Contradiction, so no such H can exist.

Consequences in industry (Rice's theorem)

Every non-trivial question about what a program does is undecidable. Real tools therefore approximate:

ToolUndecidable idealWhat it does instead
Antivirus"Is this program malicious?"signatures (regular expressions!) and heuristics; some false alarms, some misses
Compiler warnings, linters"Is this variable ever used uninitialised?"conservative analysis: may warn about safe code
Testing"Is the program correct for all inputs?"tries finitely many inputs
Compiler optimizer"Is this code unreachable?"removes only code it can prove unreachable
Part 12 · P, NP, NP-completeness

Complexity in the software industry

Before writing code, engineers ask which class a problem belongs to. P problems get exact algorithms; NP-hard problems get heuristics, approximations or exponential algorithms for small inputs; undecidable ones get conservative approximations.
