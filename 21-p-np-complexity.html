Overview

P, NP and NP-completeness in simple terms

So far this course asked "can a machine solve this problem at all?" (finite automata, PDAs, Turing machines, decidability). Complexity theory asks the next question: "can it be solved fast enough to be useful?"

The whole story on one page

TermIn one sentenceEveryday picture
PProblems a computer can solve quickly (in polynomial time).Sorting a list of names.
NPProblems whose answers can be checked quickly, if someone hands you a proposed solution.A finished Sudoku: easy to check, hard to fill in.
NP-completeThe hardest problems in NP: if any one of them can be solved quickly, every NP problem can.A master key: open one lock, open them all.

Where this sits in the course

Inside the decidable problems, complexity theory sorts problems by how much time they need. Regular and context-free membership are in P: a DFA reads a string in n steps, and CYK (Section 16) decides CFG membership in about n³ steps.

Part 1

Problems as languages

In this course a problem is a yes/no question about an input, and the problem is the language of all inputs whose answer is yes.

⟨ … ⟩ means "encode as a string". Every object (a graph, a machine, a formula) can be written as a string, so a Turing machine can read it.

Why yes/no?

Optimization questions ("what is the shortest route?") can be turned into yes/no questions ("is there a route of length ≤ k?"). If the yes/no version is hard, the optimization version is at least as hard, so studying yes/no problems loses nothing important.

Measuring time

The running time of a Turing machine is the number of steps it takes, as a function of the input length n. We care about the worst case and only about how fast the time grows: 3n² + 5n + 7 is simply O(n²).

Part 2

Polynomial versus exponential

"Fast" means polynomial time: at most nk steps for some fixed k. Exponential time like 2ⁿ grows so quickly that even the fastest computers give up at modest sizes.

Watch the growth

Why polynomial is the dividing line

  • Polynomials are closed under composition: a polynomial algorithm that calls a polynomial subroutine is still polynomial.
  • Every reasonable computer model (multi-tape TM, RAM, your laptop) simulates the others with polynomial slowdown, so "polynomial" means the same thing everywhere.
  • In practice, polynomial algorithms usually have small exponents (n, n log n, n², n³), while exponential ones become hopeless around n = 50 to 100.
Part 3

The class P

P is the set of decision problems that a deterministic Turing machine can decide in polynomial time. Informally: problems we can solve efficiently.

In one picture

A problem is in P if there is a recipe that always finds the answer in a number of steps bounded by a polynomial, with no guessing.

Part 4

The class NP: easy to check

NP is the set of decision problems where, for every yes-instance, there is a short certificate (a proposed solution) that can be checked in polynomial time.

Try it: SUBSET-SUM

Is there a subset of these numbers whose sum is exactly the target? Click numbers to propose a certificate. Checking it takes one addition per number. Finding one may require trying many subsets.

Two equivalent definitions of NP

Verifier viewMachine view
A problem is in NP if a deterministic polynomial-time machine V can check certificates: w is a yes-instance exactly when some short certificate c makes V(w, c) say yes.A problem is in NP if a nondeterministic Turing machine decides it in polynomial time: it "guesses" the certificate and then checks it. This is where the N in NP comes from: Nondeterministic Polynomial time.

The guessing is the same idea as an NFA guessing where a pattern starts (Section 2), but now the guess is a whole solution.

A common misunderstanding

NP does not mean "not polynomial". It means "nondeterministic polynomial". Every problem in P is also in NP, because a fast solver can check an answer by simply solving the problem again.

Part 5

P versus NP

We know P ⊆ NP. The open question is whether the two are equal: is every problem whose solutions are easy to check also easy to solve?

The two possible worlds

If P ≠ NP (what most researchers believe)

If P = NP

Why it matters

  • Cryptography: online banking and HTTPS rely on problems that are easy to check but believed hard to solve. If P = NP with a practical algorithm, much of this security would break.
  • Optimization: scheduling, routing, chip layout and protein folding would become efficiently solvable.
  • Mathematics: checking a proof is easy; if P = NP, finding proofs of reasonable length would be easy too.

It is one of the seven Millennium Prize Problems, with a US $1,000,000 prize for a solution, and has been open since it was stated in 1971.

Part 6

Reductions: comparing difficulty

A polynomial-time reduction from problem A to problem B (written A ≤ₚ B) is a fast way to transform any instance of A into an instance of B with the same answer. Then B is at least as hard as A: a fast solver for B gives a fast solver for A.

A reduction you can see: INDEPENDENT-SET and VERTEX-COVER

An independent set is a set of vertices with no edge between any two of them. A vertex cover is a set of vertices touching every edge. Fact: S is an independent set exactly when the remaining vertices V − S form a vertex cover. So "is there an independent set of size k?" becomes "is there a vertex cover of size |V| − k?", which is a reduction. Click vertices to build S.

How reductions are used

  1. To show B is easy: reduce B to a problem already known to be in P.
  2. To show B is hard: reduce a problem already known to be hard to B. (The direction matters: hard problem ≤ₚ new problem.)

You have seen the same idea for undecidability: reducing the halting problem to a new problem shows the new problem is undecidable.

Part 7

NP-complete and NP-hard

A problem is NP-hard if every NP problem reduces to it. It is NP-complete if it is NP-hard and itself in NP. NP-complete problems are the hardest problems in NP: solve one fast and you solve them all fast.

The first NP-complete problem: SAT (Cook–Levin, 1971)

Given a Boolean formula, can the variables be set to true/false so that the formula is true? Cook and Levin showed that the computation of any nondeterministic polynomial-time Turing machine can be written as a formula, so every NP problem reduces to SAT. Toggle the variables below.

Try it: 3-COLORING

Can the vertices be coloured with 3 colours so that no edge joins two vertices of the same colour? Click a vertex to change its colour. Checking a colouring is instant; finding one is NP-complete.

NP-hard but not in NP

The halting problem is NP-hard (every NP problem reduces to it), but it is undecidable, so it is certainly not in NP. Optimization versions ("find the shortest tour") are also usually called NP-hard, because they are not yes/no problems.

How to prove a new problem X is NP-complete

  1. Show X ∈ NP: describe a certificate and a polynomial-time check.
  2. Pick a known NP-complete problem Y (for example 3-SAT).
  3. Give a polynomial-time reduction Y ≤ₚ X: transform instances of Y into instances of X with the same answer.

Part 9

Application problems

Thirteen real-world situations. For each one, decide which class the problem belongs to, then open the full solution to check the formal problem, the certificate or algorithm, and the justification.

How to approach an application problem

  1. Strip the story: what are the objects (exams, shops, accounts) and the yes/no question?
  2. Match a known problem: graph colouring, shortest path, TSP, CLIQUE, SAT, SUBSET-SUM, KNAPSACK, the halting problem, …
  3. Certificate: if the answer is yes, what short evidence proves it, and can it be checked in polynomial time? If so, the problem is in NP.
  4. Algorithm or reduction: give a polynomial algorithm (then it is in P), or reduce a known NP-complete problem to it (then it is NP-hard), or reduce the halting problem to it (then it is undecidable).
